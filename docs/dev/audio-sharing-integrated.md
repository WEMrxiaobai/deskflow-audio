# Deskflow 一次配对的音频主程序集成版

## 用户操作

**键鼠配对成功后音频直接可用，不增加音频配对或授权。**

1. 两台或三台Windows电脑都安装1.27.6或更新的音频集成开发版，照原流程连接键鼠；已有配对直接复用。三机沿用一个键鼠server、两个client的连接方式。
2. 只在插耳机的电脑勾选 **在本机收听其他电脑**。
3. 另外一台或两台自动共享系统声音，无需设置发送模式、IP、端口、邀请码或文件。耳机可以插在键鼠server，也可以插在任一client。

收听端会显示最多两个来源，每个来源可独立调节音量、静音，设置按原配对证书身份保存，重新连接或重启后恢复。初始来源音量35%。本机应用声音继续由Windows混音，和两个远端来源一起从当前默认输出设备播放。

关闭收听开关只停音频。发送端有“停止共享本机声音”按钮，可立即停止本次共享；需要继续时可点击“恢复共享本机声音”。收听选择会记住；重启和键鼠重新连接后自动尝试恢复。没有音频单独QMessageBox或QFileDialog，没有邀请文件，没有新增音频信任库。首次原设备配对提示同时说明键鼠与系统声音共享，不增加确认次数。

## 共享时本机播放（1.27.5）

发送电脑共享期间显示 **共享时本机也播放**，默认不勾选，设置持久化。接收电脑仍只需原收听开关，不增加配对、配置页或弹窗。

- 不勾选：在UDP可信握手和采集设备打开成功之后，临时静音同一个输出设备；不改音量scalar、不改系统默认设备、不改播放器会话音量。
- 勾选：释放本程序施加的静音，远端传输不中断。共享前已经静音则保持，不擅自解除用户原静音。
- 主动停止共享、关闭收听、键鼠/TLS断开或退出：回收音频worker并恢复原静音。音频临时失败和同一配对设备重试期间保留同一个静音watchdog，避免重连间隙发送电脑突然外放；重试期间仍可点击“停止共享本机声音”恢复。固定endpoint ID同时用于采集和静音，默认设备变化后恢复旧设备再重试新会话。
- 系统或用户在共享期间修改设备音量/静音时，本次会话放弃控制，不反复覆盖；选项暂禁用，显示遵循系统设置。下次会话重新获取状态。
- 静音覆盖此输出设备的所有声音，包括通知音，不是仅静音某个应用。

独立无窗口的 `deskflow-audio-mute-watchdog.exe` 持有静音所有权，通过受限继承匿名管道和真实父进程等待句柄工作；主程序异常结束或管道断开也会恢复。无命名公共IPC、无新网络端口或授权。正常stop等待helper退出，避免恢复交错。

限制：声卡驱动是否在mute后仍提供loopback必须实测，不保证所有硬件；本机硬件测试PASS，mute前后peak比0.99998、原scalar/mute恢复一致。显式停止时若恢复失败或超时，界面会提示检查系统静音；helper自身被kill、驱动COM卡住、断电/设备拔出不能保证恢复；WASAPI无原子mute compare-and-set，最终读写间的极窄外部修改竞态无法绝对消除。用户若手动静音应尊重，不自动解除。

## 安全实现

- 直接复用原Deskflow combined PEM私钥/证书和原角色方向的trusted-clients/trusted-servers数据库，不生成音频身份或自动信任未知证书。
- GUI独立音频控制连接采用双向TLS1.2/1.3、SHA256身份pin；连接仍由原键鼠client自动发起到原server，不改变键鼠协议，所以旧peer不会收到未知键鼠消息。
- 系统参数和媒体短期随机密钥仅经此加密通道交换；不通过原world-access IPC传密钥，不写日志或邀请文件。
- 三机路由由原键鼠server协调，只转交控制消息和短期凭据；媒体由各来源直接UDP发送到收听端。地址来自认证TLS连接观察到的IPv4或IPv6地址，不信任offer自报地址；客户端使用键鼠实际连接的服务器地址。client之间的路由信任原已配对server的协调，server不解码或转发媒体。
- 每条来源有独立凭据、SSRC、UDP端点和接收会话；server仅允许该路由的收听端发布offer，发送端不能冒充收听端或协调端。接收握手检查协调端提供的来源地址，后续固定endpoint、nonce及认证上下文。
- 原键鼠停止、对应peer断开、原信任被撤销或证书变化均停止音频。2s内部heartbeat、10s无认证控制帧即断开并重试，保留1s维护粒度。
- 音频连接还须匹配当前在线键鼠 TLS 连接实际验证的证书指纹及原信任库；身份或地址缺失时不发起连接，身份改变时关闭旧连接。
- 如原键鼠关闭TLS/关闭server端peer身份检查，或证书不可读，音频fail-closed；不通过静默降级或新的音频配对绕过统一身份要求。状态文字说明等待原已验证连接，不弹音频授权。

## 路由与限制

1.27.6支持三台电脑、一个收听中心、最多两个远端来源同时混音。每来源独立解码、抖动缓冲、时钟修正和音量控制，共用一个WASAPI输出回调；某一路媒体失败时单独等待2秒重试并更换凭据，另一路保留原解码器和播放设备。来源退出、重新加入不重建健康来源。

多个收听开关同时打开时：键鼠server优先；否则保留当前仍请求收听的client；首次选择按可信身份排序。每台电脑只承担发送或接收一种角色，收听端不会把远端声音再次回传。要切换耳机所在电脑，关闭旧收听端的开关，再打开新收听端。

双来源组要求参与电脑均支持v2音频控制。存在已确认的旧版音频peer时，整组退回此前单链路机制；三机混音需三台一起更新。支持 IPv4 和 IPv6 局域网直连，client 之间的 UDP 也必须互通；IPv6 link-local 地址因作用域不可跨设备通用而被拒绝。IPv4-mapped TLS 地址可用；不提供公网/NAT 穿透或超过两个远端来源的产品支持。

音频独立worker使用现有WASAPI/Opus/SRTP链路，不阻塞键鼠。不采麦克风、不录音、不改变系统主音量。默认声卡变化/会话超时会自动重新尝试；没有实测所有设备热插拔、休眠或三机网络恢复场景，不承诺物理延迟或长期稳定性。原计划中的Windows主音量同步控件、逐来源停止传输菜单和完整发布验收仍未完成。

1.27.5修复：WASAPI采集在同一endpoint维持纯静音render流，使系统没有播放内容时仍提供loopback PCM，避免媒体时钟停走后接收端不断重连。10分钟凭据有效期只限制新握手，已连接会话持续到停止/断开；已连接UDP控制仍校验HMAC、原endpoint和本次nonce。新可信offer可替换同一peer的旧发送worker，不再因旧worker尚未退出而丢弃重连请求。失败重试使用TLS明确区分retry与主动stop，重试冷却为2秒。

握手后若一直没有成功解码的媒体包，将在超时后重试；邀请的本机时钟偏差容忍最多两分钟，签发方仍执行自己的截止时间。标准 5.1 后置、5.1 侧置和 7.1 声道按 Windows 声道掩码下混；缺失或未知的多声道掩码会被拒绝，播放输出只使用前置左右声道。22050 Hz 等采样率使用向上取整的缓冲区。底层设备的同步 COM 调用若被驱动卡住，取消操作仍可能等待该调用返回。

Windows 本地 IPC 绑定对应会话；系统 daemon 仅接受其物理控制台会话及会话 0 的 LocalSystem，前台 daemon 接受自身活动会话（可为 RDP）。GUI 校验管道服务器 PID：daemon 必须是服务管理器登记的服务进程或同会话内匹配安装目录的前台 daemon，core 必须同会话且为该服务的子进程或匹配安装目录中的 core 程序。此校验不能防御同会话进程注入、可写安装目录中的程序替换等情况，不等同于完整双向认证；跨账户、RDP 和 LocalSystem 组合仍需实机验证。系统服务不会由其他 RDP 会话控制。

## 安装

完整版保留原GUI/core/daemon、Qt/SVG/TLS插件、应用支持的语言、文档、所需VC runtime及对应源码。MSI版本1.27.11升级此前开发包；这是音频开发构建，不是Deskflow官方1.27.11发行。对应源码作为同名Sources.zip单独提供。打包前可用[精简stage脚本](../../tools/audio/prepare_minimal_stage.py)按当前二进制的导入关系选取VC运行库，并移除应用不提供的语言对应的Qt翻译；Qt动态插件予以保留。

安装会使用原升级家族并配置/重启原服务，请保存工作并主动退出旧Deskflow；需要管理员权限。仅添加Private/localSubnet防火墙：按程序限定的 core TCP（包括自定义端口）、GUI控制TCP24801、GUI媒体UDP，用户无需配置这些参数。不在Public网络自动开放。

当前宿主原CPack要求WiX4，但可用WiX3.14.1，因此[完整安装脚本](../../tools/audio/build_integrated_installer.py)收录`cmake --install`的完整stage。宿主ICE问题导致打包显式跳过ICE，数据库/压缩载荷另验，不声称完整安装升级/卸载验收已通过。安装包未数字签名，未覆盖或停止用户正在运行的旧版。

## 验证

- 单开关GUI持久化，无独立按钮/授权/文件选择窗口；真实MainWindow可容纳旧窗口尺寸，未启动core不偷偷协商。
- 隔离原风格证书+原角色信任DB：mTLS/pin、未连接name拒绝、明文拒绝、帧上限、撤销、重连、键鼠停止gate测试。
- 同一原配对信任的TLS offer/answer/stop -> 内存Session -> synthetic Opus/SRTP收发：发送1000包、解码999包，邀请文件0，信任记录没有增加。
- 新增[三窗口组回归](../../src/lib/audio/tests/PairedAudioGroupTests.cpp)：同机三个真实AudioSharingWidget、三个隔离证书身份、原风格信任库、真实mTLS和两路Opus/SRTP UDP；分别验证server/client收听、共享混音器、音量/静音与新进程持久化、单路媒体故障和TLS断开后的独立恢复、收听选举、伪造offer/plan拒绝、旧协议降级及恢复。信任文件未变、无邀请文件。
- 同一矩阵分别运行合成播放和`--render`实际WASAPI播放。后者使用合成发送音，不采集系统声音；至少100次双来源混音回调、输出有限且不超过0.98。不能据此推断物理网络、两个真实采集时钟或跨机延迟已验收。
- 本机发送端回归使用真实loopback和原生静音watchdog，覆盖勾选/取消本机播放、worker失败后重试保持静音、新offer替换、主动/远端停止恢复；最终原设备音量和静音一致。单独WASAPI smoke打开/关闭与句柄检查通过。独立音频CTest九组通过，Release的RtSafety因缺Debug CRT跳过，不能算作本轮实时分配验证。
- 尚无两台/三台物理电脑的真实音乐试听、端到端延迟测量和小时级稳定性结果；网络切换、休眠恢复、广泛设备热插拔及安装升级/卸载矩阵仍待实机验证。

三机组回归在完整Qt/音频开发环境配置后可复现：

```powershell
cmake --build build/desktop-audio --config Release --target deskflow-paired-audio-group-tests
build/desktop-audio/bin/Release/deskflow-paired-audio-group-tests.exe
# 显式使用当前默认输出播放低电平合成测试音，无系统采集或设备静音修改：
build/desktop-audio/bin/Release/deskflow-paired-audio-group-tests.exe --render
```

运行测试需要Qt/OpenSSL运行库可加载。测试会创建隔离的便携配置及证书，拒绝覆盖已有同名便携配置；不会替换或停止已安装Deskflow。默认测试不打开音频设备。
