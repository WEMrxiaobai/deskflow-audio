# 音频邀请时钟偏差修复与 1.27.5 验证

接收端按自己的系统时间生成十分钟音频邀请。发送端 GUI 原先只允许最多剩余 600 秒，而媒体层允许 660 秒；接收端时间稍快时，GUI 会静默拒绝合法邀请，不启动发送任务，接收端最终反复报 `udp-handshake-timeout`。

本次将邀请有效期、允许的正向时钟余量和剩余时间上限集中定义，使 GUI 与媒体层共用 660 秒上限。先判断过期，再做无符号时间差；已经过期的邀请仍拒绝。拒绝时记录 `invalid-audio-offer`，不记录密钥或邀请内容。

同时保留本轮现场修复：新增计算机的初始连接名称固定为 ASCII `Unnamed`，防止中文翻译“未命名”进入 core 配置导致服务端解析失败。

## 自动化证据

- 真实双向 TLS 控制连接向真实 GUI 控件发送邀请，使用现有合成媒体替身验证后台任务；不修改系统时间。
- 过期邀请和剩余 670 秒的邀请被拒绝；剩余 610 秒的合法邀请成功启动。修复前同一用例失败，修复后通过。
- 通用单元测试 30 套最终通过。SettingsTests 使用仅存在于构建副本的启动夹具，首次读取配置前提供隔离设置，再恢复原测试的非便携路径断言。I18NTests 补齐 MSVC 多配置目录下的测试翻译资源后通过。
- 音频 Release：16 项最终通过；实时堆检查按设计跳过，并补跑 Debug 对应测试通过。
- 不访问声卡的 GUI、配对控制、合成媒体、主窗口和 worker 共 5 套通过。
- 初次音频会话互斥测试与正在运行的安装版音频重试争用同一互斥锁；在其冷却间隙顺序复测通过。慢启动恢复定时测试首次失败，顺序复测通过，保留两次原始日志，不将复测结果当作长期稳定性证明。
- 全量测试首轮误运行 MSWindowsClipboardTests，该套件会清空系统剪贴板，后续自动回归排除。

日志保存在 `build/audio-handshake-hotfix/`。真实双机音频、实际声卡、安装升级与卸载仍需现场验收；本轮未停止或重启现有键鼠 core。

## 安装包

包版本为 1.27.5，基于已安装的 1.27.4 构建快照，只叠加本轮五个源码文件及包版本号；不引入工作区其他会话的新改动。应用内部版本仍为原快照的 1.27.0.0。

本轮现场角色为 wsw（192.168.77.11）键鼠服务端、win10X（192.168.77.19）客户端；音频接收在 wsw 开启，因此发送端修复必须更新到 win10X。两机安装新版后，在 wsw 开启“在本机收听其他电脑”验证；不要在 win10X 同时开启反向收听。
