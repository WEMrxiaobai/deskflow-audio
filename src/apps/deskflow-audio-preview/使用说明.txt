Deskflow 音频共享 · 双机开发预览

先跑主功能：另一台电脑的系统声音，经 Opus + SRTP 加密 UDP，在本机默认声卡播放。
这是独立的临时开发入口，不是现有 Deskflow 配对/设置界面。无需安装虚拟声卡。

【最快体验】
1. 将此整个文件夹复制到两台 Windows x64 电脑，使用同一局域网。
2. 在戴耳机的接收电脑双击“接收远端声音.cmd”。确认提示，保存一个新邀请文件。
3. 通过可信方式把邀请文件复制给发送电脑。邀请含临时密钥，不能公开或交给其他人。
4. 发送电脑先播放音乐，再双击“发送系统声音.cmd”，确认提示并打开邀请。
5. 接收电脑初始播放增益35%，请先把系统音量调低。命令窗口持续显示发送/解码计数。
6. 按 Ctrl+C 或关闭窗口停止。邀请10分钟后过期；下一轮重新开接收端、生成新文件。
   两端不用手填IP、端口、房间号或密钥。旧邀请文件请自行删除，副本不被远程删除。

【Windows 防火墙】
如果Windows询问，请只允许专用网络。程序不会自动修改防火墙、路由或系统主音量。
若连接超时，检查两台是否同网段/未开启访客隔离，以及接收端是否允许该程序入站UDP。
勿为体验关闭全部防火墙。当前仅IPv4局域网，不提供公网/NAT穿透。

【这版有意延后的功能】
- 不接现有统一配对、不开机自启、不保存设置、无多来源和GUI音量滑杆。
- 不支持自动休眠/断网/声卡变更恢复；需重开接收端并生成新邀请。
- 系统静音时有些驱动不交付采集callback，持续静音恢复可能提示重连。
- 只验证部分Windows声卡，播放callback超过10ms会明确失败。
- 发送端采集全部默认系统输出，不是麦克风，也不支持选应用。
- 同Windows会话只允许一个预览进程，避免接收声音被再次回环发送。
- 临时邀请是持有即授权的凭据，不证明设备身份；它是用户主动开发试听，不是最终安全配对。
- 编码48k stereo / 5ms，队列有界。仍未测真实两机物理延迟；不保证20–40ms或生产级稳定性。

【日志与隐私】
不保存PCM，不输出密钥；音频本地编码后加密传输。邀请文件本身明文含临时秘密，
创建时仅当前用户有文件权限，但复制后目标位置的权限由目标电脑/传输工具决定。
此程序不能保密于同一账号的恶意进程或受控机器。不要传送不希望对方听到的系统声音。

若提示缺少 VCRUNTIME140 / MSVCP140，请安装微软官方 Visual C++ 2015–2022 x64 运行库。
